# Agent Note: Web GUI 和后端作为唯一应用

Status: implemented

[English](2026-09-04-web-only-application.md) | 中文

## 问题

产品需要浏览器界面及其 Agent 后端。维护独立命令行任务执行器、TypeScript 和 Python 客户端、标准输入输出服务器以及运行时 wheel 打包，会增加产品范围之外的接口和分发工作。浏览器仍然依赖配置加载、Agent 引擎、工具、权限和持久化会话，因此将启动器与这些共享服务一起删除会破坏应用。

## 决策

[后端入口](../../../../apps/server/src/index.ts)直接启动 Web 应用。固定的 `web` 配置保留基础与 Web Bundle 层、Harness 主目录存储、用户补丁文件以及可选的单次启动覆盖层。后端负责进程就绪和等待资源全部停止后的关闭。服务器包是私有包，不提供 npm 命令行可执行文件。

仓库不提供独立 SDK、无界面任务执行器或 ACP 服务器应用。浏览器的 API 控制器和传输仍属于后端。面向模型的终端工具以及调用外部 Agent 的 Provider 继续受支持；Codex Provider 拥有其私有 JSON-RPC 行传输，因为它是该辅助代码保留的使用方。内部基础配置测试驱动器保留核心录制会话测试，不提供另一个产品入口。

## 考虑过的替代方案

**保留精简的公开 CLI。** `dsh web` 命令能以较少工作保留启动器，但所需产品仅包含浏览器和后端。直接启动服务器可移除命令分派及无关应用选择。

**只保留浏览器文件。** 没有后端，浏览器无法执行 Agent、访问工作区或持久化会话。共享运行时是产品必需代码。

**保留 SDK 代码但排除构建。** 排除构建可减小分发体积，却仍需维护产品不提供的接口所对应的源码、配置和文档。

## 影响

独立 CLI 和 SDK 集成不可用，包括独立进程自动化和 Python 捆绑的无需系统 Node 的运行时分发。源码树和构建覆盖更少的应用模式；这不承诺降低稳定运行时的内存占用，因为 Web 进程原本就加载其自身组合。外部插件包仍然是配置依赖，其安装和 Bundle 成员关系通过 Web 配置目录中的包清单管理，而非产品 CLI。

Web 回归覆盖必须同时测试后端进程入口和组装后的浏览器应用，包括启动、流式聊天、模型设置、工具执行、审批、子 Agent 和持久化会话。从已移除执行器套件借用的夹具保留在其 Web 所属目录下。重新引入独立客户端需要明确的产品需求，以及独立维护的协议和分发测试。
